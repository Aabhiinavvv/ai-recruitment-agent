# AI Recruitment Workflow Platform (React + TypeScript + Vite)

A modern, recruiter-supervised recruitment workflow and intelligence platform rewritten in **React 19**, **TypeScript**, and **Tailwind CSS**, preserving all original business logic, multi-dimensional scoring frameworks, fairness policies, proctored AI interview tooling, and organizational architecture.

---

## 🌟 Core Features & Modules

### 1. Recruiter-Supervised Hiring Workflow
- **Hiring Brief & Role Templates:** Preloaded presets for AI/ML Engineer, Frontend Engineer, Backend Engineer, DevOps Engineer, Full Stack Engineer, Product Manager, and Data Scientist.
- **AI Job Intelligence Agent:** Drafts inclusive, unbiased job descriptions and multi-dimensional evaluation rubrics.
- **Recruiter Review & Approval Gate:** Recruiter oversees and approves the JD before distribution checklists are generated.
- **Resume Screening & Multi-Dimensional Scoring:** Evaluates candidate resumes across 6 weighted dimensions:
  - Technical Skills (30%)
  - Experience (20%)
  - Education (10%)
  - Projects (15%)
  - Domain Knowledge (15%)
  - Communication (10%)
- **Adaptive Assessment Rounds:**
  - **Coding Round:** Adaptive prompt generation, code submission testing, and multi-factor evaluation (Correctness, Approach, Complexity, Strengths).
  - **Technical Interview:** Dynamic role-specific questions, evidence evaluation, and recruiter pass/reject decisions.
  - **HR Round:** Structured phone guide, alignment notes, and human review.
- **Outreach & Communication Queue:** Auto-drafts personalized interview invitations and respectful update messages with full editing and plain-text export.
- **Workforce & Talent Relationship Graph:** Descriptive node-link entity network linking roles, candidates, verified skills, and interview outcomes.

### 2. AI Online Video & Voice Interview
- **Real-Time Proctor & Motion Detection:** WebRTC/getUserMedia video stream with optical frame-difference analysis, detecting abnormal movement spikes and logging snapshots for recruiter review.
- **Live Voice Interaction:** In-browser Speech Recognition (`SpeechRecognition` / `webkitSpeechRecognition`) and Text-to-Speech playback (`speechSynthesis`).
- **Real-Time AI Evaluation:** Scored responses out of 10 with actionable improvement feedback and session summaries.

### 3. Agent Platform Architecture
- Visual representation of the **Four-Layer Platform**:
  1. *Layer 1:* Agent Workforce (planning, task routing)
  2. *Layer 2:* Company Memory (opt-in candidate history & workforce graph)
  3. *Layer 3:* Reasoning Engine (evidence reflection, prompt generation)
  4. *Human Approval Gate:* Recruiter authorization for high-impact decisions
  5. *Layer 4:* Execution Engine (workflow transitions, dispatch drafts)

### 4. Fairness & Bias Auditing (EEOC §60-3.4)
- **AttributeMasker:** Automatic redaction of protected demographic tokens (Name, Gender, DOB/Age, Nationality, Marital Status, Religion) prior to AI evaluation.
- **A/B Experiment Benchmark:** Disparate Impact (DI), Demographic Parity Difference (DPD), and EEOC 4/5ths rule compliance monitor.

### 5. Candidate Intelligence & HR Policy Agent
- **Grounded Resume Q&A:** Direct evidentiary answers based on candidate resume profiles.
- **Actionable Resume Enhancements & Generator:** Metric-driven improvement suggestions and one-click formatted resume download.
- **Employee HR Policy Agent:** Grounded answering of organizational policies (leave, PTO, remote work, expenses).

## Python Backend — Agent 1: Job Intelligence

The existing React + Vite frontend now calls a separate FastAPI backend for the first agent.

### Run the backend

~~~powershell
cd backend
python -m venv .venv
.venv\\Scripts\\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
~~~

The backend API documentation is available at http://127.0.0.1:8000/docs.

### Enable local LLM generation

Install Ollama, start its local service, then pull the configured model:

~~~powershell
ollama pull qwen3:4b
~~~

The backend can still run without Ollama. In that case it returns a clearly labelled deterministic template draft rather than pretending the output was generated by an LLM.

### Agent 1 API

- GET /health
- POST /api/v1/job-intelligence/draft

The Job Intelligence Agent is built with LangGraph, FastAPI, Pydantic and a local Ollama adapter. It generates a structured job description and evaluation rubric, asks clarifying questions when essential requirements are missing, and flags potentially sensitive selection criteria for human review. Every draft requires company approval before it can be published.

### Run backend tests

~~~powershell
cd backend
pytest -q
~~~

## Python Backend — Agent 2: Candidate Intelligence

The Agent 2 panel is available at the top of the Hiring Workflow screen. Upload up to 15 PDF, DOCX or TXT resumes in one batch. It returns structured profiles with extracted contact fields, skills, experience, education, projects, source evidence IDs/snippets, confidence values and review flags.

- API: POST /api/v1/candidate-intelligence/resumes/batch
- Multipart fields: repeated files and consent_confirmed=true
- Limits: 10 MB per file; 15 files per batch
- Each resume is processed independently; a failure for one file does not stop the batch.
- Files are processed in memory and are not persisted by this endpoint.
- Profiles are extraction-only. Agent 2 does not rank, shortlist, reject or make hiring decisions.

Core dependencies: PyMuPDF, python-docx and python-multipart. Optional engines (Docling, spaCy, Presidio and PaddleOCR) are configured separately. See backend/README.md for setup, privacy and production limitations.


## Agent 3 — Matching & Ranking

Agent 3 compares Agent 2's structured profiles with an Agent 1 job rubric that the recruiter has approved. It produces a ranked evidence-alignment index, criterion-level explanations, required/preferred skill evidence, evidence coverage and review flags.

- API: POST /api/v1/matching/candidates
- The browser only enables matching after the recruiter approves the job brief.
- Agent 3 receives only job-related candidate fields: skills, work/education/project entries, evidence snippets and extraction flags. Candidate names, contact details, location and profile URLs are not sent to the matching API.
- BM25 evidence retrieval is enabled in the core install. BGE-M3 semantic retrieval and BGE reranking are optional extras.
- Criteria with insufficient information are marked not evaluable and excluded from the score denominator. Evidence coverage is shown separately.
- The index is an advisory evidence summary, not a hiring probability or autonomous decision. Recruiters must review the original resume and source evidence.

The approval gate in this prototype is enforced by the browser workflow and a client-supplied API field; it is not yet backed by authenticated user permissions or a persistent approval record. Production deployment must enforce approval server-side.


## Agent 4 — Communication Agent

Agent 4 generates candidate-facing email drafts and optional human call scripts using recruiter-approved workflow state.

Supported draft types: application acknowledgement, interview invitation, scheduling request, schedule confirmation, status update, non-progression notice and follow-up.

- API: POST /api/v1/communication/drafts
- Requires explicit contact authorisation confirmation.
- Interview invitation/scheduling drafts require the candidate to have an explicit recruiter-advanced decision.
- A non-progression draft requires an explicit recruiter non-progression decision.
- Sensitive personal/health information and score/rank references in free-text context are omitted with a warning.
- Outputs remain drafts and join the existing recruiter approval queue.
- No SMTP, email, SMS, WhatsApp, calendar dispatch or telephony integration is enabled. Approval does not mean the message was sent.


## Agent 5 — AI Interview Agent

Agent 5 prepares a structured question plan from the recruiter-approved job description and evaluation rubric, then provides evidence-focused review of individual, consented interview answers.

- Prepare questions: POST /api/v1/interviews/plan
- Review an answer: POST /api/v1/interviews/evaluate
- Uses the configured local Ollama model when available. A deterministic, clearly labelled question fallback is used if generation is disabled or unavailable.
- Answer evaluation produces an advisory 1–5 rubric score only when the local model returns valid structured output. If the model is unavailable, the system returns a manual-review checklist and no score.
- Interview inputs are restricted to candidate ID, approved job context, rubric criteria and consented answer text. The API does not accept a candidate resume, contact details or profile attributes.
- Candidates must have an explicit recruiter decision to advance; the job must be recruiter-approved; and candidate consent must be confirmed.
- Every evaluation remains pending human review. The agent cannot pass, reject, shortlist or hire a candidate.
- The frontend supports recruiter-led text interviews, answer capture, per-answer review and JSON export.

Prototype limits: no autonomous candidate-facing voice agent, audio/video recording, facial/emotion analysis, automated proctoring, database persistence, transcript storage, calendar integration or interview dispatch. The API processes requests statelessly; the export is generated in the browser. Use an authenticated, access-controlled, audited persistence layer and validated candidate consent records before production.


## Agent 6 — Background Verification Agent

Agent 6 prepares a consent-gated verification checklist for a recruiter-advanced candidate and validates reviewer-entered evidence metadata.

- Create a verification case: POST /api/v1/verification/cases
- Record a reviewed check: POST /api/v1/verification/reviews
- Supported checks: identity, employment, education, address (only when necessary and lawful), professional licence, and candidate-authorised professional reference.
- Requires a recruiter-approved job, an explicit recruiter decision to advance, and candidate authorisation before a case can be created.
- Verified or discrepancy outcomes require a human reviewer attestation, a source-checked flag, an authorised source type and an opaque evidence reference.
- The API rejects common raw personal identifiers and document numbers in evidence summaries/notes; it does not accept uploaded identity documents or identity-number fields.
- All outcomes remain subject to recruiter review. A discrepancy or inability to verify is not an automatic rejection.

Prototype limits: no identity-document upload, Aadhaar/PAN/passport number processing, employer/institution/government database lookup, criminal-record check, provider API call, candidate notification, database persistence or final hiring decision. No provider has been contacted. Provider integrations require an authorised licensed provider, candidate-specific consent, jurisdiction-specific legal review, secure credentials, access controls, retention policy and auditable results.


## Agent 7 — Offer Management & Onboarding Agent

Agent 7 creates a non-binding offer draft from recruiter-supplied terms, records recruiter-attested offer lifecycle events, and prepares an onboarding task checklist after an offer is recorded as accepted.

- Create offer draft: POST /api/v1/onboarding/offers/drafts
- Record offer event: POST /api/v1/onboarding/offers/events
- Create onboarding plan: POST /api/v1/onboarding/plans
- Update onboarding task: POST /api/v1/onboarding/tasks/events
- Offer preparation requires the approved job, a recruiter-recorded final hire decision, background verification review attestation, zero unresolved verification items and all mandatory offer terms.
- Compensation, currency, work mode, work location, dates, probation, benefits and additional terms are supplied explicitly by the recruiter. The agent does not invent compensation or legal clauses.
- Offer status transitions are explicit: draft → approved → manually sent outside platform → accepted/declined, with withdrawal and expiry paths.
- Onboarding can be prepared only for an accepted offer with recruiter start approval.
- Task ownership is assigned to HR, manager, IT or candidate; task changes require human attestation.
- JSON/text exports are generated in the browser.

Prototype limits: no offer email dispatch, e-signature, legally binding contract generation, HRIS/payroll integration, document collection, IT account provisioning, equipment ordering or database persistence. Agent 6 verification results are not automatically linked to Agent 7 because the current prototype is stateless; the verification-complete flag is a recruiter attestation. Use approved secure HR/legal/payroll systems for actual offer issuance and onboarding.
